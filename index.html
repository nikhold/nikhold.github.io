Vending Machine FSM

  • Context: ECE 212 (Fundamentals of Logic Design) | Timeline: Spring 2026
  • Languages & Tools: Breadboarding, Digilent WaveForms, Verilog/SystemVerilog, Testbenches, EDA Playground
  • Summary: Designed a multi-input Vending Machine FSM in both Verilog and on a breadboard with Digilent WaveForms signals.

The objective of this project was to engineer an optimized, multi-input Vending Machine FSM that could be demonstrated on a breadboard and in Verilog. The Verilog FSM is slightly different than the breadboard FSM in order to produce a cleaner waveform graph, however the inputs and outputs are the same for both.

View Engineering Deep-Dive

Engineering Challenges

Challenge 1: Breadboard Wiring

  • The Problem: During initial construction of the breadboard project, I ran into multiple issues with the wiring of the breadboard due to the large number of logic gates, causing hours of debugging and a huge delay in project completion.
  • The Solution: To cut down on any more debugging time, I shortened resistors and reconstructed the circuit from scratch. Since I already had the layout planned, this allowed me to cut down on the number of logic gates. After this, no wiring issues persisted and the project was completed at a rapid pace.

Challenge 2: Verilog Debugging

  • The Problem: During the testing phase of the Verilog project, I kept running into timing issues with the generated waveform graph from the provided testbench in EDA Playground.
  • The Solution: Using the generated logs and after a lengthy debugging process, I found and corrected a bug in my FSM that caused incorrect state transition logic. Project code is maintained in a private repository to comply with NC State academic integrity policies and is available for review upon request.

Key Deliverables

  • Completed optimized breadboard that emulates a Vending Machine accepting nickles and dimes
  • Verilog RTL Model to emulate similar but differing Vending Machine functionality

"The Greatest Game" Program

  • Context: ECE 209 (Computer Systems Programming) | Timeline: Spring 2026
  • Languages & Tools: C, CMake, CLion IDE, Gemini 3.1 Pro
  • Summary: Created a program to determine the "best" game on Steam in 2021 based on formula of weighted scoring criteria.

The objective of this project was to implement a program that would determine the "greatest" game on Steam in 2021 based on a formula of weighted criteria that the program would get by extracting the needed files from a .zip folder, then parsing a .csv file for the calculation data, then parsing the same .csv again for other stats, before finally parsing a .JSON file for more stats to display on the final readout. (For anyone interested, the "greatest" game on Steam in 2021 is PUBG, based on the weighted calculations) This program utilizes linked list traversal, multi-file I/O, and multi-file parsing.

View Engineering Deep Dive

Engineering Challenges

Challenge 1: .csv File Parsing

  • The Problem: Properly parsing the provided .csv file and correctly calculating each games weighted score.
  • The Solution: Re-reading the project specifications document to understand further context about the .csv file's formatting. Further debugging used to identify calculation error and utilization of Gemini to troubleshoot possible solutions and causes. Project code is maintained in a private repository to comply with NC State academic integrity policies and is available for review upon request.

Challenge 2: Implementing External Libraries

  • The Problem: Due to the use of multiple different file types, external libraries needed to be implemented to properly parse these files. Since we used an online platform for code testing and grading, these libraries had to be portable and lightweight for uploading.
  • The Solution: After some in-depth research, I discovered miniz and cJSON, libraries that worked with .zip and .json files respectively, that were contained in a single file and could easily be dropped into my program.

Key Deliverables

  • C Program that implements external libraries and analyzes multiple file types to determine the "Greatest Game" on Steam.

Home Server

  • Context: Personal | Timeline: Spring 2026 - Present
  • Languages & Tools: Linux CLI, Proxmox VE, Ubuntu, Docker Compose, Bash, Tailscale
  • Summary: Created a custom device ecosystem to give me and my home tailored access to various self-hosted services

The objective of this project is to create a custom device ecosystem to self-host various services and deliver them to my devices (and most importantly, having fun doing it). Using Proxmox VE as my base, I host various Virtual Machines with various services (such as Nextcloud, Pihole, Home Assistant, etc.) and can access them from anywhere using Tailscale.

View Engineering Deep Dive

Engineering Challenges

Challenge 1: Automated Docker Volume Backups

  • The Problem: Preventing data loss and service downtime by Docker volume corruption, deletion, or other screw-ups.
  • The Solution: Highly configurable and scalable custom Bash scripts that run a temporary Alpine container and .tar.gz Docker volume contents, and vice versa. Future improvement with a dedicated server running Proxmox Backup Server utlizing a local disk and Backblaze B2 for offsite storage pending. Due to a minor data loss incured when switching from Ubuntu to Proxmox VE, I no longer have the scripts.

Challenge 2: Power Failure Safeguard

  • The Problem: To ensure longer service uptime and extend hardware life, I needed a constant source of power that would be protected againt outages and flickers, thereby protecting critical data and preventing system crashes.
  • The Solution: LiFePO4 UPS system monitored by NUT (Network UPS Tools) for uninterrupted service access and safe shutdowns.

Key Deliverables

  • Proxmox VE server running VMs hosting Home Assistant, Nextcloud, etc. with Tailscale running for secure, abroad access
  • Low-power Raspberry Pi server for service monitoring
  • Configured UPS system to ensure constant power flow for critical devices and services.
